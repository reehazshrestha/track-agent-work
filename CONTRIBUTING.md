# Contributing

Keep the skill portable, concise, and useful for real coding work.

1. Describe the workflow problem and a concrete scenario.
2. Change instructions or templates in `skills/track-agent-work/`.
3. Keep template links valid and avoid duplicate guidance.
4. Walk through a small task, a resumed task, and a handoff. Check that existing docs are reused, attribution is preserved, and unrun checks cannot be presented as passed.
5. Validate frontmatter with your available skill validator. Record what you actually checked in `docs/STATUS.md`.
6. Explain the behavior change and validation in your pull request.

Do not add project-specific deployment rules, mandatory agent spawning, secrets, raw transcripts, or an unnecessary framework. Changes that require scripts should explain why instructions alone are insufficient.
